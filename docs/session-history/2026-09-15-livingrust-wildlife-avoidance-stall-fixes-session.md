# 2026-09-15 LivingRust session — wildlife avoidance, stall-rescue overhaul, base-design persistence

## Context
Resumed from the 2026-09-07 session. Server had advanced from Rust build 97→103 overnight but the plugin still compiled clean (unlike the 09-07 session's opening). Spent the session live-testing successive 125-150 bot batches against the 09-07 checklist, and root-caused/fixed several real bugs along the way — a genuinely productive, fix-heavy session.

## What shipped (all built clean, hot-reloaded, and live-verified)

1. **Repath-failure log spam fix** ([LivingRust.Commands.cs](../../TemplateProject/Plugin/LivingRust.Commands.cs)) — a failed repath was logging on literally every tick (20/s) instead of the "once per repath" the old comment claimed, because `needsRepath`'s own `corners.Count==0` check re-fires every tick once a path has failed. Now throttled to the 1st failure + every 20th tick. Retry/give-up timing unchanged, only logging volume.

2. **Wildlife hard-avoid for Bear/Crocodile, gear-score-gated** (Combat.cs, HomeSiteStrategy.cs, Commands.cs) — root cause of ~85% Bite-death rate this session: the existing "fight anything with a melee tool, rock included, at any cost" design didn't distinguish a boar from a bear. Bear is now hard-avoided below GearScore 30, Crocodile below GearScore 50 (everything else — Wolf2/Boar/Polarbear/Panther/Tiger — unchanged, "everything else normal" per explicit scoping). Two layers:
   - **Proactive**: `AdvanceAlongPath` scans 50m for a hard-avoid animal once per repath cycle and bends the immediate path target sideways around it (`ComputeHardAvoidDetourPoint`), without ever touching the survivor's real destination. Falls back to the real destination if the detour itself fails to path.
   - **Reactive**: `StartCombat` intercepts any Bear/Crocodile attacker before the armed/melee branches and flees instead, regardless of weapon.
   - Also pulled Bear/Crocodile out of `TryFindNearestHuntableAnimal` (deliberate meat/hide hunting) below their thresholds.
   - **Verified 100% effective live**: zero "engaging 'bear'"/"engaging 'crocodile'" lines in a 150-bot, 30+ minute trace after deploy — they only ever appear in "steering around"/"hard avoid, fleeing" lines now.
   - **Real finding once Bear/Croc stopped dominating deaths**: Wolf2/Boar/Panther/Polarbear became the new dominant killers (241/130/27/24 engagements in one window) — overall death rate didn't drop as much as expected, because those species were left intentionally unchanged. Worth revisiting if it still looks disproportionate next session.

3. **Keycard-tier destination bias** (GearScore.cs, CardPuzzles.cs) — a bot holding a green/blue/red keycard now gets a flat +40 weight boost toward the matching monument tier (Green→Tier1/Low, Blue→Tier2/Medium, Red→Tier3/High) when rolling its next loot destination, so a keycard already in inventory is more likely to actually get used instead of sitting dead weight while gear score drags the roll elsewhere. Stacks if holding multiple tiers.

4. **En-route resource gathering** (Looting.cs, ResourceGathering.cs) — the 09-07 parked idea, actually built: during a long-distance walk, bots now scan a 20m radius for real tree/ore nodes (not just small collectible pickups, which were already handled) and do a full gather stop, capped at 2 tree stops + 2 ore stops per walk (persists across en-route detours, only resets on a genuinely new destination roll). Checked before the Collectible category so a real node takes priority over a loose pickup.

5. **Stuck-bot rescue ladder overhaul** (Commands.cs) — this was the big one, three rounds:
   - Lowered `LifeStallTimeoutSeconds` 30→15s.
   - Added `TryRawNearbyRelocate` as a genuine last-resort tier after `TryEmergencyTeleport`/`TryForceRelocateIgnoringCollision` both fail — skips the ground-probe entirely (which was the actual failure point: "no real ground found within the probe window") and instead picks a nearby point with Y clamped to within 5m of the survivor's own current elevation, checking only physical obstruction. Radius tuned down from an initial 30-80m (looked "wild"/wrong on a perfectly fine road/jungle spot) to 5-15m per live feedback.
   - **Real bug found and fixed**: `RescueGenuinelyStalledSurvivor` was written on the false assumption that "the survivor's own main loop picks a fresh goal next cycle" after setting `CurrentTask = None`. There is no such loop — the whole task pipeline is a pure callback chain (`StartWalking`'s `onArrived` chaining into the next step, confirmed via `StartLootForResourcesTask`'s own doc comment: "no separate task-tick timer"). Every successfully-relocated survivor was being permanently orphaned, sitting motionless until the next stall check caught it and repeated the same pointless relocate — live evidence: dozens of bots relocating every ~15-20s forever, zero real activity in between. Fixed by explicitly calling `StartLootForResourcesTask` after a rescue, same re-entry pattern every other interrupt-and-resume case in the project already uses.
   - **Rate-limited the watchdog itself**: traced live rubber-banding (player-reported, "surely this isn't bottlenecking...") to `RunLifeStallWatchdog` firing 121 rescues in the exact same second — each rescue chains up to 16+ physics/ground-probe queries, so a 121-bot burst meant 1000+ expensive queries in one tick of Rust's largely single-threaded main loop. Root cause of the clustering: every plugin reload re-baselines all survivors' stall snapshots simultaneously, phase-locking a chunk of the population's 15s clocks together. Added `LifeStallMaxRescuesPerTick = 5` — scan stays cheap and unlimited, but only 5 actual rescues fire per 5s tick; anyone over budget just waits untouched for the next tick instead of being skipped. Verified live: no group ever exceeds 5, backlog drains steadily, no bot starved.

6. **Base-design/home-site persistence fix** (Models/Character.cs, LivingRust.Persistence.cs, LivingRust.Hooks.cs) — two-part fix for "bots keep re-rolling a different base design":
   - Death-reset: `_rolledBaseDesign`/`_pursuingBaseGatherGoal` were being wiped on every death for a still-base-less survivor, same block as every other per-life flag. Explicitly excluded from that reset now (Lucas's ask) — real gathered resources still don't survive death (normal Rust inventory-on-death), this only keeps the *choice* of design stable.
   - **Bigger, non-obvious root cause found live**: `18SharpJackal` re-rolled its home-site strategy AND base design 3 times *without ever dying*. Traced to `_rolledBaseDesign`/`_hasRolledHomeSiteStrategy`/`_pursuingBaseGatherGoal` being plain in-memory fields, never part of the persisted `Character` record (`CaptureAllLiveState` only ever saved Position/Rotation/Health/Inventory/Spawned) — so *every one of this session's ~17 hot-reloads* was silently wiping these for every currently-alive survivor, not just deaths. This had been invisible before today because a confused bot used to just silently idle (bug #5 above) instead of actively re-rolling. Fixed properly: added `HasRolledHomeSiteStrategy`/`RolledBaseTier`/`RolledBaseDesignPath`/`RolledBaseCost`/`PursuingBaseGatherGoal` as real persisted `Character` fields, wired into `CaptureAllLiveState`/`RestoreSpawnedSurvivors` the same way position/inventory already are.
   - **Verified live**: 8 base-gather rolls in the window right after this deploy, every single one a genuinely new bot reaching the stage for the first time — zero re-rolls, versus the repeated re-rolling pattern seen constantly before the fix.
